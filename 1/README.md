# 色探しゲーム プロトタイプ

お題の色を、記憶や言葉だけを頼りにフィールド（静止画・動画）の中から探し出すゲームのプロトタイプです。
設計思想と課題は [DESIGN.md](DESIGN.md) を参照してください。

このプロトタイプは **1 台の PC を交代で使うホットシート方式** です。本来の目標である 1 人 1 台の形にどう移行するかは DESIGN.md の「8. 1 人 1 台への移行方針」にまとめています。

## 必要なもの

- Python 3.9 以降（標準ライブラリのみ使用。`pip install` は不要です）
- Chromium 系ブラウザ（Microsoft Edge / Google Chrome）の最新版
  - Firefox / Safari でも動作する想定ですが、動作確認はしていません。

## 素材の置き場所

| 種類 | 置き場所 | 対応形式 |
|---|---|---|
| 静止画（案 1） | `assets/images/` | `.png` `.jpg` `.jpeg` `.webp` `.bmp` `.gif` `.avif` |
| 動画（案 2） | `assets/videos/` | `.mp4` `.m4v` `.webm` `.ogv` |

- サブフォルダに入れても読み込まれます。ファイル名に日本語を使っても問題ありません。
- 素材を追加・削除したら、ブラウザでページを再読み込みしてください（サーバーの再起動は不要です）。
- 素材が 1 つもないとゲームを開始できません。

### 素材の推奨条件

- **静止画は sRGB の PNG を推奨します。** JPEG はブロックノイズのせいで「3x3 の範囲で色が揃っている場所」が減り、お題の候補が少なくなります。
- **動画は H.264 の MP4 か VP9 の WebM（SDR）を推奨します。** HDR の動画は、ブラウザやディスプレイによって色が変わるため使わないでください。
- 動画は 1080p 以下、長さは 10 秒〜3 分程度が扱いやすいです。4K でも動きますが、ラウンドの準備に時間がかかります。
- 色の種類が多く、色が同じで広い領域がある素材ほどゲームとして面白くなります（風景、街並み、雑貨、イラストなど）。
- 真っ黒・真っ白に近い色（L\* < 8 または L\* > 97）と、色ムラの大きい場所は、お題として選ばれません。

## 起動方法

プロジェクトのフォルダ（`server.py` があるフォルダ）で次のコマンドを実行します。

```
python server.py
```

ブラウザが自動で開きます。開かない場合は、表示された URL（既定は `http://127.0.0.1:8000/`）を開いてください。終了するには `Ctrl+C` を押します。

ポートを変える場合は次のように指定します。

```
python server.py --port 8080
```

> `index.html` をダブルクリックして直接開く（`file://`）方法では動きません。ブラウザのセキュリティ制限で、ローカル画像のピクセルを読み取れないためです。必ず `server.py` を経由して開いてください。

## 遊び方

### 記憶モード（個人戦）

1. 「お題を見る」を押すと、お題の色が中間グレーの背景の上に設定した秒数だけ表示されます。このとき、他の人は画面を見ないでください。
2. 表示が終わるとすぐに探索が始まります。お題は二度と見られません。
3. フィールドをクリックして色を選びます。制限時間内なら何度でも選び直せます。
4. 全員が終わると結果が表示されます。

### 伝達モード（2 人 1 組のチーム戦）

1. 伝える人だけがお題の色を見ます（観察時間）。必要なら探す人に見せるメモを書けます。
2. 探す人に交代し、探索を始めます。伝える人は口頭で説明してかまいません（ハウスルールで禁止することもできます）。
3. 伝える人と探す人はラウンドごとに交代します。
4. 説明の声は相手チームにも聞こえるので、チームごとに「別の色で、見つけやすさが同程度」のお題が出ます。

### 探索画面の操作

| 操作 | 内容 |
|---|---|
| クリック | カーソル位置の 3x3 平均色を選ぶ |
| 矢印キー | 選んだ位置を 1px 動かす（Shift を押しながらだと 10px） |
| Enter | 選んだ色で決定する |
| Space | 動画の再生 / 一時停止 |
| `,` / `.` | 動画のコマ送り（1/30 秒単位） |

- 右側のルーペは 15x15 ピクセルを拡大表示します。白枠の中が判定に使う 3x3 の範囲です。
- 動画は一時停止中だけ色を選べます。
- 時間切れになったときは、最後に選んだ色が提出されます。一度も選んでいなければ 0 点です。

### 採点

- お題色と選んだ色の差を CIEDE2000（ΔE00）で測ります。
- 点数は `100 × exp(−ΔE00 / k)` で計算します。k は設定画面の「採点の甘さ」で、既定値は 10 です。
- PERFECT（ΔE00 ≤ 1）〜 MISS（ΔE00 > 20）の段階表示は、見やすさのためのラベルです。点数そのものは連続的に変わります。
- 探す人の色覚タイプを設定すると、お題色と選んだ色の両方をその色覚での見え方に変換してから ΔE00 を計算します。

## フォルダ構成

```
color-search-game/
├── README.md           このファイル
├── DESIGN.md           設計思想と課題
├── server.py           ローカルサーバー（静的配信・素材一覧 API・動画用 Range 対応）
├── package.json        単体テスト用（実行時には使いません）
├── assets/
│   ├── images/         ← 静止画をここに置く
│   └── videos/         ← 動画をここに置く
├── tests/
│   └── logic.test.js   色計算・お題選定・進行ロジックの単体テスト
└── web/
    ├── index.html
    ├── css/style.css
    └── js/
        ├── main.js         画面遷移とゲーム進行
        ├── game.js         ルール・手番・順位（DOM 非依存）
        ├── scoring.js      採点（DOM 非依存）
        ├── color.js        色空間変換・CIEDE2000・色覚シミュレーション（DOM 非依存）
        ├── sampler.js      3x3 平均・色ムラ判定・お題選定（DOM 非依存）
        ├── field.js        画像・動画の読み込みとラウンド準備
        ├── search-view.js  探索画面（ルーペ・選択・動画操作）
        ├── screens.js      設定・受け渡し・お題提示・結果画面
        ├── config.js       調整用パラメータ
        ├── timer.js        カウントダウン
        └── dom.js          DOM ヘルパー
```

ゲームバランスに関わる値（お題候補の色ムラの上限、明度の範囲、ルーペの倍率など）は `web/js/config.js` にまとめています。

## 単体テスト

Node.js 18 以降があれば、プロジェクトのルートで次のコマンドを実行できます（追加パッケージは不要です）。

```
node --test
```

## 検証状況

作成した環境で実際に確認した内容は次のとおりです。

- **単体テスト（Node.js 24）**：10 件すべて成功しました。CIEDE2000 は Sharma らの検証データ 12 組と小数第 4 位まで一致しました。ほかに、sRGB → Lab の基準値、色覚シミュレーション、採点、お題選定、手番の順番、順位表を確認しています。
- **サーバー（Python 3.12）**：次の動作を curl で確認しました。
  - 素材一覧 API が正しく返る
  - `.js` の Content-Type が正しい
  - Range リクエストに 206 と 416 を正しく返す
  - パストラバーサルとディレクトリ一覧の要求は 404 になる
- **ブラウザでの通しプレイ（Linux 上のヘッドレス Chromium、Playwright で自動操作）**：次の流れを確認し、コンソールにエラーは出ませんでした。
  - 記憶モード × 静止画：選んだ位置の色が元画像のピクセル値と一致すること、時間切れで NO PICK になることを確認しました。
  - 記憶モード × 動画（VP9 WebM）：再生、一時停止、コマ送り、フレームを指定した選択ができました。
  - 伝達モード 2 チーム × 2 ラウンド：役割の交代とメモの受け渡しができました。
  - ゲームの中断ができました。

確認していないことは次のとおりです。

- Windows での実行
- Edge / Firefox / Safari での動作
- H.264 の MP4 の再生（テストに使った Chromium は H.264 に対応していないため）
- 高 DPI 環境での見た目
- タッチ操作
