# 星座パズルゲーム 設計メモ

## 1. コンセプト

- ランダムに生成した星空から、お題の形（星座）を見つけ、一筆書きでなぞって結ぶパズルゲーム
- 正解は盤面上にただ一つだけ存在する
- 対象：一人で遊ぶ暇つぶし。電車の中で遊べるハイパーカジュアルに近いミニゲーム
- 対戦は当面入れない（ソロのみ）

## 2. プラットフォーム

- 開発・試作：PC（マウス操作）
- スマホへの移植を前提に、操作はドラッグ（なぞる）方式で統一する

## 3. ゲームモード

### エンドレスモード（当面はこれのみ）

- 残り時間はカウントダウン方式
- 正解すると残り時間が加算される
- 問題が進むほど難易度が上がる
- 時間切れでゲーム終了

## 4. お題と一致の定義

- お題は「点（星）＋線（辺）」で構成される図形
- 盤面上の正解は、お題を以下の変形で配置したもの
  - 平行移動
  - 拡大縮小
  - 回転
- 左右反転は許可しない
- 難易度に応じて許可する変形を段階的に増やす
  - 序盤：移動のみ
  - 中盤：拡大縮小を追加
  - 後半：回転を追加

## 5. 一筆書きルール

- お題の図形は必ず一筆書きできるものにする
  - 出ている線の数が奇数の星が 0 個または 2 個であることを生成時に保証する
- 一つの星から 3 本以上の線が出る（分岐する）図形も許可する
- 判定は「正しい辺をすべて、同じ辺を 2 度通らずに、つながった 1 本の線で引けたか」で行う
  - 特定の順番を正解として扱わない

## 6. 操作

- 最初の星を押し、押したまま次の星へなぞっていく
- ボタン（指）を離すと、それまでの線はリセットされる
- 星の当たり判定は見た目より大きくし、ドラッグ中は近い星へ吸い付くようにする
- ミスによる時間ペナルティは無し（失うのはやり直しにかかる時間のみ）

## 7. 星の色

- 明るさは端末ごとに見え方が異なるため使用せず、色で区別する
- 色は 7 色程度に固定する
- 基本は白。色付きの星はレア
- 色は一意性を確保するための手段として使用する（アンタレスのように一部の星に色を付ける）

## 8. 盤面生成

- 星空をランダムに生成し、お題を変形して配置する
- 意図的なダミー形状（ニアミス）は配置しない
  - 星が多いと偶然似た形ができることは許容する
- 正解以外に一致する形がある場合は、色を使って一意にする

## 9. シード値

- 盤面生成にシード値を使用する
- 「ゲーム全体のシード＋問題番号」から各問題の盤面が決まる構造にする
- 生成のやり直し（再配置・色付けなど）にも、すべて同じシード由来の乱数を使う

# 今後の課題

## A. 一意性の検証（最優先）

- [ ] 一致判定のアルゴリズムを実装する
  - 星を 2 点選ぶと変形（移動・拡大縮小・回転）が一つに決まるので、それでお題の残りの点が別の星に重なるかを全ペアで調べる（計算量はおよそ O(N² · k)）
- [ ] 「一致」とみなす許容誤差（閾値）を決める
  - 目安：星の当たり判定の半径程度
  - 閾値より近い偽の一致は色付けか再配置で解消し、それより遠い「似ているが違う形」は許容する
- [ ] 一意性の解消手順を決める（色付け → それでも駄目なら再配置 → 盤面の作り直し）

## B. 色の詳細

- [ ] 7 色の具体的な色（白を含めて 7 色か、白＋7 色か）を決める
- [ ] 色付けの対象を決める
  - 正解側の星だけに色を付けると「レア色＝答えの近く」と推測されやすい
  - 偽の一致側の星に色を付ける、ランダムな色付き星も混ぜる、などで推測を防ぐ方法を検討する
- [ ] 色付き星の出現率を決める
- [ ] 色の見分けやすさを試作で確認する（小さな点で 7 色を区別できるか、色覚の多様性への配慮として形やにじみ方を変えるか）

## C. 盤面生成の品質

- [ ] お題の辺が別の星のすぐ近くを通らないようにする（A→C なのか A→B→C なのか区別できなくなるため）
- [ ] 線同士の交差を許可するか決める
- [ ] 画面の密度の上限（星が密集しすぎて操作できなくならない数）を決める
- [ ] 画面比率は縦長（9:16 程度）を基準とし、座標を正規化する

## D. 操作の詳細

- [ ] 間違った辺へなぞったときの扱いを決める（線を引かせない／その場でリセット）
- [ ] 一筆書きで行き詰まったときの扱いを決める（離してやり直すだけでよいか）
- [ ] 正解・不正解・完成時の視覚フィードバック（音を出せない環境を想定）

## E. 難易度の段階設計

- [ ] 問題番号ごとに何を解禁するかの表を作る

| 段階（例） | 変形 | お題の形 | 星の数 |
|---|---|---|---|
| 序盤 | 移動のみ | 3〜4 点、分岐なし | 少ない |
| 中盤 | ＋拡大縮小 | 4〜5 点 | 増やす |
| 後半 | ＋小さな回転 | 分岐あり | 増やす |
| 終盤 | 360° 回転 | 5 点以上 | 密度の上限まで |

- [ ] 星の数以外の難易度の軸（お題の点の数、分岐の有無、回転の幅、拡大縮小の幅）の上げ方を調整する
  - お題の点が少ないほど紛らわしくなる点に注意する

## F. タイムとスコア

- [ ] 初期の残り時間
- [ ] 正解時の加算時間（固定か、速く解くほど多く加算するか）
- [ ] 後半で「平均解答時間 > 加算時間」となり、必ずどこかで時間切れになるように調整する
- [ ] スコアの定義（正解数のみか、速さボーナスを加えるか）

## G. 救済策

- [ ] 見つからないときのヒントまたはスキップを入れるか決める
  - 候補：始点の星を光らせる（代償として残り時間を減らす）

## H. UI・演出

- [ ] 完成時の演出
